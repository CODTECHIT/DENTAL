- [ ] **WhatsApp chat** (`wa.me/918686325269`) floating button + pre-filled message "Hi, I'd like to book a dental appointment at Sri Shobh Dental".
- [ ] **Booking form** with only 4 fields (name, phone, service, preferred time) + immediate success screen with "Call now" fallback.
- [ ] One primary CTA per page; contrasting button color; "Book Free Consultation" micro-offer for first-time patients.
- [ ] Trust badges near CTA: "7 MDS specialists · Same-day emergency · 100% hygienic · Transparent pricing".

### Trust & credibility
- [ ] Live Google reviews (widget) on homepage + each service page.
- [ ] Doctor credentials with photos on every relevant page (file 02 employee list already builds entity).
- [ ] Before/after gallery (consent-cleared, no identifiable faces) + "case studies" labels.

### UX/performance (drives conversions directly)
- [ ] Mobile-first: single-column, thumb-reachable CTAs, no intrusive popups (Google penalty risk + bad UX).
- [ ] Page load < 2.5s (file 06 §18) — every 100ms costs bookings.
- [ ] Map embed + "Get Directions" link on contact/homepage.
- [ ] After-hours notice + emergency call-out box when closed.

### Measurement
- [ ] GA4 events: `begin_checkout` (form open), `generate_lead` (submit), `call_click`, `whatsapp_click`, `map_click`.
- [ ] Google Ads (if used): call tracking + form micro-conversions.
- [ ] Monthly funnel review: visits → form/call → confirmed appointment → attended.

## 24. Schema Validation Checklist

### Validate with (run after every deploy + monthly)
- [ ] Google **Rich Results Test** (richresultstest.withgoogle.com) — paste URL, confirm FAQ, LocalBusiness, AggregateRating rich results detected.
- [ ] Google **Schema Markup Validator** (validator.schema.org) — check JSON-LD parses with 0 errors.
- [ ] **GSC Enhancement reports**: FAQs, Local Business, Review snippets — fix any "invalid" items.
- [ ] **Screenshot test** on a real Google SERP (incognito) to confirm snippet display.

### Checklist per page
- [ ] Valid JSON (no trailing commas, escaped quotes) — parse via validator.
- [ ] `@id` URLs resolve to the exact page canonical; no duplicate `@id`s.
- [ ] NAP in schema = GBP = footer = citations.
- [ ] FAQ questions match visible page H2/H3 copy.
- [ ] `openingHoursSpecification` matches GBP hours (and special hours in GBP).
- [ ] `AggregateRating` present ONLY with ≥5 real reviews; `reviewCount` == actual.
- [ ] `Review.reviewBody` is verbatim patient text (not fabricated).
- [ ] Images referenced in schema exist and are served over HTTPS.
- [ ] No schema on `noindex` pages; no schema on thank-you pages.
- [ ] Breadcrumb positions start at 1, no gaps.
- [ ] Area pages: `areaServed` matches the page H1 location.
- [ ] One JSON-LD block per page (use `@graph`), loaded in `<head>`.
- [ ] Monthly: re-run validator + check GSC "Page indexing"/"Rich results" for drops.

## 25. GEO — Generative Engine Optimization (ChatGPT, Gemini, Claude, Perplexity, Copilot)

### Goal
Make AI assistants cite **Sri Shobh Dental & Implant Centre** as the confident, factual answer for "best dentist in Tukkuguda / Maheshwaram / near me".

### GEO tactics

**1. Entity clarity (the #1 lever).** AI engines build entity graphs from consistent NAP + schema. Keep name/address/phone/website 100% identical across GBP, site, schema, directories, socials. Add founder + all 7 doctors as `Person` entities (done in file 02) — named experts boost trust for health queries.

**2. Answer-first content.** Structure every page as: direct answer in first 40–80 words → evidence → details. AI engines truncate to the first concise, factual passage (file 04 provides the exact Q&A bank).

**3. Data + specifics > generic claims.** AI citation is driven by verifiable facts: "7 MDS specialists", "single-visit RCT", "CAD/CAM zirconia crowns", "beside HP Petrol Bunk, opposite JK Supermarket, Srisailam Highway", "Mon–Sat 10:00–20:00". Numbers, locations and hours get quoted verbatim.

**4. Structured Q&A at scale.** Publish the 50 AEO answers + PAA questions as FAQ schema AND visible H2 sections. Both Google's featured snippets and LLM RAG pipelines prefer Q&A formats.

**5. Authoritative third-party endorsements.** IDA membership, Practo/Justdial profiles with high ratings, Google review snippets, media mentions, guest posts. AI engines weigh external corroboration of the entity heavily.

**6. Freshness & E-E-A-T for health (YMYL).** Medical content needs author byline (doctor name + credentials), last-reviewed date, citations to sources (IDA/ADA guidelines), and regular updates. Add "Medically reviewed by Dr. X (BDS, MDS)" badges.

**7. LLM-crawlability.** Ensure full HTML server-render (Nitro SSR) with no client-only critical content; keep robots.txt open; XML sitemap listed; no heavy JS-gated content that AI crawlers can't read. Perplexity/Copilot use Bing — ensure Bing Webmaster Tools + Bing Places profile (also feeds Copilot).

**8. Local authority aggregation.** High NAP-consistent citations across Practo, Justdial, Lybrate, Sulekha create redundant entity signals that LLMs cite when aggregating "best dentist near X".

**9. Monitor & measure (monthly).** Run the same prompts in ChatGPT, Gemini, Claude, Perplexity, Copilot: "best dentist in Tukkuguda", "dental implants near Maheshwaram", "where should I go for a root canal in Tukkuguda". Log whether/where the clinic is recommended, and iterate on any hallucinated or outdated facts (correct by publishing/clarifying content + keeping GBP hours/phone current).

**10. Answer disambiguation queries.** Publish content for "Is Sri Shobh Dental good?" / "Sri Shobh Dental reviews" / "Sri Shobh Dental Tukkuguda address" — brand + review queries train AI engines to recommend confidently. Keep the same phrasing across pages so LLMs match the entity name verbatim.
